## Key engineering decisions

1. **Pure-Python utility extraction** — Every module isolates state-machine / arithmetic / parsing logic into a `utils/` package with no Odoo imports. Tests run via plain pytest at ~0.25s for 154 cases — no Postgres, no Odoo runtime, no CI tax.
2. **Unique sys.modules mounting in conftests** — Each per-addon conftest mounts utility files under uniquely-prefixed names, avoiding the `utils` and `services` top-level collisions that would otherwise break a single `pytest usbea_tests/` invocation.
3. **OCA extension strategy documented per module** — `MODULES.md` declares for each new module whether it extends OCA (`dms`, `partner-contact`) or greenfields (justification given).
4. **LGPD consent gate enforced at the model layer** — `@api.constrains` on `res.partner.usbea_archetype` refuses to save donor/volunteer/grantee archetypes without an active consent record. The error message guides the user to the fix.
5. **AI calls never silently fail** — Router exhausts retries then raises typed `AIProviderError`; pillar code catches and writes a `usbea.ai.suggestion` row with `error` set so the UI can surface "AI unavailable" without crashing the parent workflow.
6. **State machines are pure Python** — `validate_transition` returns a `TransitionResult` dataclass with a descriptive reason on failure; the Odoo model raises `UserError(check.reason)`. Same pattern across `usbea_grants_seeking.utils.pipeline`, `usbea_compliance_br.utils.dsar_sla`, etc.
